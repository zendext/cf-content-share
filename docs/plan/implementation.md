## 第一批：短链、权威状态与恢复

根目录 `src/`、`migrations/`、`tests/` 是正式服务工程；`prototypes/compat/` 保留独立构建、数据模型和验证用途。正式服务复用原型验证过的 Rust/Wasm 依赖版本、MCP HTTP 传输和 Access JWT 验签方式。

已实现：

- 仅 `describe`、`invoke` 两个 MCP 工具。目录、参数 Schema 和分发引用同一份 Rust 定义；详情提供结果说明、副作用与示例。完整目录现有 14 项操作：`resource.create_url/list/get/update/delete`、`session.create/list/revoke`、`operation.list/get/retry`、`storage.get`、`stats.query/samples`。
- 密码学随机的 12 位大小写字母／数字 ID；D1 唯一约束冲突重试。资源与创建操作通过同一 D1 batch 事务登记，参数冲突返回 `IDEMPOTENCY_CONFLICT`；旧创建请求重试返回资源当前状态。
- 管理元数据编辑、目标 URL 编辑、永久逻辑删除。删除保留 ID、标题和创建操作映射，清除目标、描述及标签；不能恢复删除的资源。
- 已发布资源的关键词包含搜索、完整标签交集、类别与创建时间筛选。列表按 `created_at DESC, id DESC` 分页，默认 20、最多 100；游标绑定列表种类和筛选条件。详情返回最后登记的操作，其他操作通过分页查询读取。
- 匿名 GET/HEAD 短链跳转，`302` 与错误响应均 `no-store`。KV 缓存只含公开映射；没有可用 KV 时查询 D1 主库，数据库故障返回 `503`，不存在返回 `404`。
- KV 快照有效期为主库读取前时刻加 60 秒；命中不续期，延迟回填也不续期。写入成功仅表示平台接受，不代表所有节点已同步。物理 KV TTL 为 120 秒。
- 每次管理写入先持久登记 KV 任务，随后尝试同步。Cron 每 5 分钟按索引取最多 25 项到期任务；通过 60 秒执行占用与 Token 条件更新防止重复领取和旧执行者覆盖结果。KV 恢复总是读取 D1 当前状态。
- 首次同步失败后等待 5、10、20、40 分钟，随后每次 60 分钟；自动尝试最多 10 次，之后进入 `needs_attention`。手动重试重新排期并重置本轮计数，保留累计尝试数和最后失败信息；已完成或有效占用中的任务不重置。

参数的可执行定义以 [`src/catalog.rs`](../../src/catalog.rs) 和 MCP `describe` 为准。当前时间字段使用 UTC Unix 秒，范围为 `[created_from, created_to)`。标题最多 512 字符、描述和 URL 最多 8192 字符、标签最多 32 个且各不超过 128 字符；不接受重复标签、未知字段或显式 `null`。空字符串／空数组用于清空管理字段。幂等指纹将未提供的标题、描述、标签分别视为空字符串、空字符串、空数组，其他参数值（包括标签顺序）须相同。

操作状态和资源状态分别返回。`last_error` 是保留的最后失败信息，即使之后成功也可能存在，应结合 `status`、`steps` 和 `next_retry_at` 判断当前进度。响应不包含执行 Token、原始平台异常或内部幂等指纹；平台异常通过稳定的业务码表达。公开错误不返回管理诊断。

## 本地验证与证据

执行入口见[根 README](../../README.md)。测试使用官方 MCP SDK、真实 workerd 的 D1/KV 和编译出的 Wasm；JWT 使用测试 RSA 密钥，JWKS 只在外部请求边界提供测试响应。故障夹具仅由测试入口引入，正式构建入口不包含故障开关或认证绕过。

首批提交通过了 Rust 格式、Wasm Clippy（警告视为失败）和 16 项端到端测试；这些检查保留在当前完整回归中，验证：

- JWT 错误签名、签发方、audience、期限和算法；Origin、协议版本、请求体上限与两个工具的严格参数。
- 创建重试、6 个并发请求、参数冲突、D1 事务回滚、响应丢失后查询；注入 ID 冲突后不覆盖旧墓碑。
- 编辑后跳转、HEAD、删除与旧操作重试；字面 `%`／`_` 搜索、中文搜索、标签交集、时间和游标分页。
- KV 读取／写入失败、主库回源与双重故障 `503`；坏缓存、过期缓存、命中不续期。
- 暂停旧 KV 回填，在其间删除资源并推进测试时钟，旧快照仍按原时间失效。
- 真实 scheduled 入口的退避、10 次上限、手动恢复、活动占用不被接管、多个 Cron 争抢、旧占用者无法确认新任务，以及第 10 次执行中断。
- KV 成功但 D1 确认中断，操作仍能查询并在占用过期后恢复。

本地迁移通过 Wrangler 连续应用两次，第二次显示无待执行迁移；本地配置的 `deploy --dry-run` 打包通过。实际启动 Wrangler 本地服务后，未认证 `/mcp` 返回 401、缺失资源返回 404、本地 scheduled 触发返回 200。这些证据不代表云端跨节点传播、完整服务部署升级或统计可见性已验收。
