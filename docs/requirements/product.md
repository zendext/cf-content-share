# cf-content-share 产品需求

- 状态：首版需求与技术方案已确认；尚未实现，关键兼容性待验证。
- 更新日期：2026-10-11。
- 使用场景：单人自部署、自用。

本文是首版功能需求与验收标准的基线；实现方案见[技术设计](../design/technical.md)。文档中的预期行为不表示服务功能已经实现或通过验证。

## 1. 产品定位

将网址、图片和其他文件变成可访问、可管理、可统计的分享链接，通过 Agent 完成管理。

产品以内容分享为中心：网址生成跳转链接，图片生成可直接展示的链接，其他托管文件默认下载。所有内容共享资源标识、管理能力和访问统计。

项目基于 Cloudflare 生态自行实现，不提供自建管理 GUI。MCP 是管理入口，公开分享地址使用普通 HTTPS，访问者无需使用 MCP。

## 2. 已明确的范围与约束

1. 支持创建外部 URL 短链，以及上传本地图片和其他文件；不支持远程文件 URL 导入。
2. 管理操作及统计查询通过 MCP 提供，只暴露 `describe` 和 `invoke` 两个工具，具体业务能力作为 operation 按需发现。
3. 只有一位使用者，管理入口必须认证；不提供多用户归属、用户间授权、协作或管理员角色体系。
4. 每条内容拥有自动生成的独立短 ID，不以原文件名作为唯一标识，不提供自定义别名。
5. 短链允许修改目标网址并保持分享地址不变；图片和其他文件不允许覆盖原内容，更新必须创建新资源。
6. 访问统计属于正式功能。接受 Cloudflare 分析采样误差，不接受程序分支造成的漏采集、重复采集或错误计算。
7. 默认不限制内容数量或创建频率。
8. 总存储容量和单文件大小上限为可选配置，默认不额外设置产品上限；平台自身限制仍然适用。
9. 基础设施必须对应实际需求，优先采用简单、可维护的方案。

持有分享链接即可访问，链接持续有效直到使用者主动删除资源。公开读取不需要管理凭据，公开访问者不能据此获得管理或统计查询权限。

首版不提供私有内容、访问密码、指定访问者、自动到期、回收站或删除恢复；不承诺音视频在线播放和 PDF 预览，也不提供图片内容编辑。

## 3. 内容与资源模型

底层统一表达为：短 ID → 资源记录 → 对外响应。

| 资源类别 | 保存的内容 | 公开访问行为 |
| --- | --- | --- |
| 外部引用 | 目标 URL 和管理元数据 | 返回 HTTP 重定向 |
| 托管图片 | 文件、文件属性和管理元数据 | 返回可直接展示或嵌入的图片 |
| 其他托管文件 | 文件、文件属性和管理元数据 | 默认下载原文件 |

图片属于托管文件的一种。资源与操作状态由 D1 保存，具体数据模型见技术设计。

### 3.1 资源标识与分享地址

- 服务端生成 12 位随机大小写英文字母和数字组成的短 ID，通过 D1 唯一约束防止冲突。
- 多次上传同名文件，必须生成互不冲突的资源记录。
- 原文件名作为显示或下载信息保存，不参与资源唯一性判断。
- 资源 ID 与分享地址在资源存续期间保持稳定；删除后不得将旧 ID 分配给另一条内容。
- 完整公开 URL 可以由部署域名和资源 ID 生成，无需逐条持久保存完整 URL。
- R2 对象 key 可以由资源 ID 按固定规则生成；如果与 ID 解耦，必须持久保存对应关系。
- 使用单个可配置域名，分享地址统一为 `https://s.example.com/r/<id>`；网址、图片和其他文件共用此格式，不带类型、原文件名或扩展名。`s.example.com` 为部署域名示例。
- 管理入口为同域名下的 `/mcp`，上传入口为 `/upload`；首版不支持自定义别名。

### 3.2 管理元数据

| 范围 | 信息 |
| --- | --- |
| 公共记录 | 资源 ID、资源类别、创建时间 |
| 外部引用 | 目标 URL |
| 托管文件 | R2 文件定位信息、原文件名、内容类型、实际字节大小、SHA-256 |
| 管理信息 | 可选的标题、描述、标签；首版支持填写、编辑、搜索或筛选 |

文件属性以服务端核验结果为准。标题、描述和标签属于管理元数据，编辑这些信息不修改文件字节，也不改变分享地址。

普通管理编辑按单人使用设计，以最后一次成功写入为准，不增加客户端版本号和编辑冲突协议。已删除资源拒绝继续编辑。

图片宽高、是否为动图、音频时长、艺术家等类型专属属性不纳入首版。后续版本应能通过数据模型迁移为已有文件补充属性，无需重新上传，且保持资源及分享链接可用；首版不提前增加这些字段或解析任务。

### 3.3 搜索与分页

- 关键词在标题、描述、原文件名中按连续文本包含匹配，任一字段命中即可；ASCII 英文字母不区分大小写，中文不自动分词。
- `%`、`_` 等字符按普通文字查询；类型、标签、创建时间等筛选条件与关键词条件组合生效。
- 资源列表按创建时间从新到旧返回，默认每页 20 条、最多 100 条，使用游标继续查询。
- 列表返回基本元数据与分享链接，详情另行查询；Agent 按任务需要继续翻页，服务端不一次返回全部记录。

## 4. 首版功能基线

| 编号 | 功能 | 预期行为 |
| --- | --- | --- |
| FR-01 | 创建 URL 内容 | 保存目标网址，分配独立短 ID，返回分享地址；访问后跳转到目标 |
| FR-02 | 上传托管内容 | 上传本地图片或其他文件，建立资源记录，确认上传完成后返回可用分享地址；不提供远程文件导入 |
| FR-03 | 列出与查找内容 | 分页列出资源，按资源类别、原文件名和创建时间筛选；支持标题和描述搜索、标签筛选 |
| FR-04 | 查询内容详情 | 返回资源信息、文件属性和分享地址 |
| FR-05 | 删除内容 | 认证后永久删除资源；分别报告逻辑删除、KV 更新和文件清理状态，允许传播延迟及后台清理；历史统计按保留期限继续可查 |
| FR-06 | 查询单条内容统计 | 按时间范围返回访问次数、时间趋势、来源及地区分布 |
| FR-07 | 查询汇总与排行 | 返回全部内容或指定类别在时间范围内的汇总统计及热门资源，包含保留期内已删除资源的统计 |
| FR-08 | 编辑短链目标 | 修改目标网址，保留原资源 ID 与分享地址；允许 KV 传播延迟，统计继续按同一资源累计，不按历次目标拆分 |
| FR-09 | 编辑管理信息 | 编辑标题、描述和标签，不修改托管文件内容 |
| FR-10 | 查询访问样本 | 查询 Cloudflare 实际可返回的访问样本，支持筛选和限制返回量；不承诺完整访问日志 |
| FR-11 | 管理上传会话 | 通过已认证的 MCP 建立和撤销应用级上传会话；Token 可用于多次上传，有效期 24 小时 |
| FR-12 | 查询与恢复操作 | 按状态查询操作列表，查看各步骤、最后错误和重试状态；需要处理的操作支持修正问题后手动恢复重试 |
| FR-13 | 查询存储占用 | 返回已发布、上传预留、待清理文件等占用明细及可选容量限制 |

### 4.1 管理认证与 Agent 边界

- 首版面向 Codex 和 Hermes Agent；客户端必须能够读取本地文件并执行 HTTP 上传。MCP 服务端不能直接读取客户端文件路径。
- MCP 使用 Cloudflare Access Managed OAuth，身份提供方使用 Cloudflare，策略仅允许使用者本人。接受该平台能力的 Beta 状态，实际客户端兼容性必须验证。
- OAuth 成功后，通过 MCP 建立应用级上传会话；应用 Token 用于 HTTP 上传，不要求每个文件重新授权。
- 应用 Token 有效期固定为 24 小时，支持主动撤销；到期后通过仍有效的 MCP 认证获取新会话。若 OAuth 会话本身失效，需重新登录。
- Cloudflare OAuth 撤销不会自动撤销已经签发的应用 Token；它仍可能有效至应用侧撤销或到期。这一边界已接受。
- 返回结构化结果，明确每一步的实际状态、错误和可重试性，不把部分完成压缩成含糊的整体成功。

### 4.2 上传与重复请求

- 文件经 HTTP 上传，由 Worker 流式中转到 R2；首版不提供分片上传、断点续传或 R2 直传。
- Agent 提交文件大小和 SHA-256，服务端核验实际字节大小并利用 R2 校验摘要；失败或未完成时不得报告发布成功。
- 创建短链和上传文件采用操作级幂等。同一次操作的重试沿用操作标识，已成功时返回原资源；主动再次创建使用新标识，即使文件相同也生成独立资源。
- 同一个操作标识携带不同的文件大小、摘要或创建参数时，返回明确的参数冲突。
- 响应丢失后，Agent 先查询原操作状态；已经成功则直接取回分享链接，避免重新传输。文件已写入但发布未完成时，返回处理中或待恢复，不能仅凭文件存在就报告成功。
- 上传完成后直接返回发布结果，不要求另调用一次 MCP 确认发布。摘要校验不用于文件去重。

图片和其他文件更换内容时，必须作为新资源上传并生成新 ID。旧资源仍提供旧文件，直到主动删除。

### 4.3 文件展示

图片直接展示或嵌入，其他文件默认以原文件名下载，不提供媒体播放器或 PDF 预览承诺。

SVG 原样保存，以 `image/svg+xml` 返回，由浏览器渲染；不增加 CSP 沙箱、脚本禁用、外部资源拦截或内容清洗，不转成位图。浏览器自身的规则照常生效。

## 5. 访问统计

### 5.1 正式统计能力

- 单条资源在指定时间范围内的访问次数。
- 按天或小时聚合的访问趋势。
- 请求来源及访问地区分布，具体规则见 5.3。
- 指定资源类别和时间范围下的汇总与热门排行。
- Cloudflare 实际可查询的访问样本，具体边界见 5.4。
- 所有统计均可通过 Agent 接口查询，不依赖用户进入 Cloudflare Dashboard。

统计与样本查询必须通过管理认证，返回结构化结果供 Agent 解释或展示。

### 5.2 统计口径

基础口径是到达服务、成功跳转或成功返回完整／部分文件内容的 GET 请求，不代表人眼观看次数、独立访客数或完成下载次数。首版不要求 UV 或按访问者去重。

- 浏览器使用本地缓存而未发送网络请求时，不产生新的服务端访问事件。
- 每个符合口径的请求采集一次，服务端响应缓存命中时也必须采集，不得因处理分支不同而漏记或重复采集。
- 分段下载、重试产生的新请求分别计数，不合并为一次下载。
- 机器人和链接预览按同样规则计数，不尝试识别人类访问。
- HEAD 请求、失败请求及因资源已删除而被拒绝的请求不计入访问次数。
- KV 删除状态传播期间，若请求仍实际成功返回文件或执行跳转，正常计数；不额外查询 D1 排除这些成功请求。
- 不同资源类别可以分别报告跳转请求、图片读取请求和文件读取请求。
- Analytics Engine 查询必须考虑采样权重，不能直接把记录行数当作访问次数。
- 接受 Cloudflare 自身采样引入的估算误差，结果应明确其采样或估算性质；不承诺固定误差百分比。
- 短链目标修改前后的访问归于同一资源，可按时间范围查询，但不提供按历次目标拆分。

### 5.3 来源与地区

- 采集请求实际携带的 `Referer` 原文，不在采集时仅保留域名；没有提供的信息不补全，缺失时表示未知。
- MCP 统计结果可以按需要提取域名、分组或格式化；格式化不得取代原始来源值，访问样本可以展示 Cloudflare 返回的原文。
- 地区以 Cloudflare 实际提供的信息为准，优先满足国家／地区统计，不强求省、市级；缺失时表示未知。

### 5.4 访问样本与能力边界

- 统计和样本查询以 Cloudflare Analytics Engine 实际提供的能力为边界。
- 支持按资源、时间范围等条件筛选，默认每次 20 条、最多 100 条，按游标分批查询，不一次返回全部数据。
- 查询结果是可获取的访问样本，不保证每一次访问都有可查询明细，也不保证翻页能够还原全部访问。
- 样本结果应保留可获取的采样权重及原始字段，避免将一条样本解释为一次精确访问。
- 不自行增加完整访问日志存储，不另做采样、采样补全或为还原访问记录而重复保存数据。

### 5.5 查询期限、延迟与故障

- 产品提供最近 30 天的统计与访问样本查询，过期数据可以丢弃，不要求终身累计值或长期聚合存档。
- 30 天是产品查询范围，不要求 Cloudflare 恰好在第 30 天物理删除底层数据。
- 正常情况下，符合口径的访问应在 5 分钟内反映到统计结果，不要求即时更新；这是实现联调需要验证的目标。
- 删除资源不清除保留期内的统计。汇总与排行仍包含这些访问，并将对应资源标记为“已删除”，保留用于辨认统计对象的必要基本信息，例如资源 ID 和标题。
- 统计采集故障不阻断分享，继续提供文件或跳转。对可检测的故障记录异常，不将已知受影响的数据伪装成完整数据，也不要求另存访问日志补回。
- 查询失败必须明确报错，不得伪装成零访问量；故障不能作为程序漏采集或重复采集的正常理由。

### 5.6 时间口径

- 底层时间统一使用 UTC；查询接受明确的起止时刻，并支持指定统计时区。
- 默认时区为 `Asia/Shanghai`，可通过部署配置修改；小时和日期分组使用本次查询的时区。
- “今天”“昨天”等自然语言由 Agent 转成明确时间范围；MCP 返回实际查询范围和采用的时区。

## 6. 缓存与删除

浏览器缓存与服务端缓存分别处理：

- 图片和文件内容不可覆盖，浏览器使用一年缓存，响应为 `Cache-Control: private, max-age=31536000, immutable`；首版不专门实现 ETag 协商缓存。
- 可修改目标的短链使用 `302` 和 `Cache-Control: no-store`。
- 服务端通过 Worker 内的 Cache API 缓存文件，读取文件缓存前仍检查 KV 资源状态。KV 未命中、过期或读取失败时回源 D1。
- 管理接口、认证相关响应和失败响应不进入公开内容缓存；共享缓存不得绕过 Worker 的资源检查和统计逻辑。

删除和目标修改采用最终一致性：

- 删除为永久操作，不提供回收站或恢复；重新上传或创建必须得到新资源和新分享地址，旧 ID 永不复用。
- 删除与短链目标修改允许通常约一分钟、偶尔更久的传播延迟，不承诺 60 秒上限，也不承诺跨节点立即生效。
- 逻辑删除、KV 更新被接受、R2 文件清理完成是不同状态。MCP 必须分别报告，KV 接受写入不能表述为所有节点已经同步。
- 可以先完成逻辑删除，再由后台重试文件清理；尚未清理的文件仍计入存储占用。不能只删除管理记录而遗留无人处理的文件。
- 删除状态生效后，到达服务端的请求必须被拒绝，包括文件仍在边缘缓存中的情况。局部缓存清除不能当作全局失效证明。
- 浏览器已经缓存或用户已经下载的副本可能长期可用，不承诺收回；这些本地复用不产生服务端访问事件。

### 6.1 未完成操作的恢复

- D1 保存操作及待完成步骤；同一个 Worker 每 5 分钟通过 Cron 查询到期任务，无任务时立即退出。
- 可恢复工作包括 KV 同步、R2 清理，以及完整文件已经上传但发布尚未完成的收尾。后台不能替 Agent 重新上传本地文件。
- 可重试错误按 5、10、20、40 分钟、随后每小时一次的间隔退避；实际执行由 Cron 调度，不保证精确到秒。
- 每轮自动重试最多 10 次，之后标记为 `needs_attention`；明确不可重试的错误直接进入需要处理的状态。手动恢复可开始新一轮，保留累计尝试次数和已有失败信息。
- MCP 可查询失败步骤、最后错误、重试次数和下次重试时间；修正问题后可手动恢复重试。停止重试不等于操作完成，也不能因此释放未清理文件的容量。
- 参数错误、认证失败、容量不足和文件摘要不匹配不由后台盲目重做；失败产生的残留仍需清理。
- 活跃上传不得被清理任务误删，预留容量必须在确认上传结束且残留清理完成后释放。

## 7. 自部署与成本边界

- 单人自用，默认不设置内容条数上限、每日新增条数上限或创建频率限制。
- 总存储容量和单文件大小上限为可选配置，默认不额外设置产品上限，不另设用户容量配置。
- 配置限制后，超限上传必须明确拒绝并说明原因；底层平台的实际限制始终适用。
- 上传实现必须遵守平台能力，并核验实际文件大小；配置了容量限制时，并发上传不得绕过限制。
- 总容量占用口径为“已发布文件 + 正在上传的预留空间 + 已删除但尚未清理的文件”。上传前原子预留，发布时转为实际占用，清理确认完成后释放；各状态不得重复计入。
- SHA-256 校验需要 Agent 在上传前读取本地文件计算摘要，这部分准备时间属于已接受的传输取舍。
- 不因费用预设下载流量 GB 配额。R2 Standard 的费用由存储占用和操作次数构成，出站流量免费。
- 短期分享后清理文件可以减少后续存储占用，但每日峰值仍计入存储用量，不能承诺短期大容量内容必然免费。
- 使用缓存仍可能产生 Worker 请求与 CPU 消耗；统计采集也必须纳入用量观测。
- 部署者应能查看实际资源用量、失败请求及费用相关指标。

首版采用 Wrangler 命令行构建和部署，提供资源初始化及数据库迁移流程；Access/OAuth 按文档完成一次配置。初始化重复执行时复用已有资源，升级不重建存储或改变已有分享地址。敏感凭据使用 Worker Secrets。

首版不提供已发布内容的自动到期清理；失败残留清理不属于内容自动到期。R2 免费存储额度不是产品硬上限，实际费用与账户其他项目共用的额度以 Cloudflare 为准。

## 8. 已确认的技术方向

详细方案见[技术设计](../design/technical.md)。以下为已确认、待实现的组件分工，不代表实际服务或兼容性验证已经完成。

| 组件 | 职责 |
| --- | --- |
| Rust/Wasm Worker | 单个 Worker 承载 MCP、HTTP 上传、公开访问及后台恢复，使用 workers-rs |
| Cloudflare Access | Managed OAuth 与单人身份准入，按管理路径保护 |
| D1 | 权威资源记录、管理元数据、上传会话、操作状态、容量与已删除资源的必要标识 |
| Workers KV | 公开读取所需的短 ID 映射与资源状态，允许最终一致性 |
| R2 Standard | 托管文件的持久存储 |
| Cache API | 在 Worker 内缓存公开文件响应，命中时仍经过访问采集逻辑 |
| Workers Analytics Engine | 接收访问事件，按平台采样能力提供聚合统计与可查询样本 |
| Cron Triggers | 每 5 分钟扫描 D1 中到期的未完成操作 |
| Workers Logs / Metrics | 观察请求、错误和运行用量 |

公开访问路径：

```text
请求 → Worker 查询 KV（未命中、过期或读取失败时回源 D1）
     → 无效资源：拒绝
     → 有效网址：302 跳转
     → 有效文件：读取 Cache API／R2 后返回
     → 按实际响应采集访问事件
```

首版不引入 Durable Objects Alarm、Queues、Code Mode 沙箱或图片转换服务。Rust/Wasm 是实现语言选择，不承诺比 TypeScript 更快或更省费用。

## 9. 实现前验证与依赖

以下是实现与联调需要取得的证据，不重新开放已确认的产品范围：

| 主题 | 必须验证的内容 |
| --- | --- |
| Rust 与 MCP | 所选 Rust MCP 传输能在 Workers/Wasm 运行，并与 Codex、Hermes 实际完成发现及调用 |
| OAuth 与路径 | Access Managed OAuth、JWT 校验、单域名路径准入与 OAuth 发现能协同工作，公开访问不被管理认证拦截 |
| 流式上传 | 不完整缓冲文件；大小与 SHA-256 核验、平台请求上限、响应丢失及中断恢复均符合约定 |
| KV 与缓存 | KV 回填和同步不会永久恢复旧状态；删除状态检查不能被缓存路径绕过，浏览器长期缓存行为符合约定 |
| 统计 | 各成功响应分支恰好采集一次，采样权重、时区、有限样本查询及正常 5 分钟可见性得到验证 |
| 后台恢复 | Cron 能发现已登记但中断的步骤，不误清理活跃上传，不重复发布或重复释放容量，重试上限可验证 |
| 部署与升级 | 初始化可重入，数据库迁移保留现有资源和 ID，已有链接及后续类型属性扩展不需要重传文件 |

若平台能力或联调结果不能满足已确认要求，必须明确差异并重新确认，不能用文档调查代替实际运行证据，也不能静默切换实现语言、认证方式或降低验收标准。

## 10. 验收标准

以下为后续实现的验收目标，不表示目前已通过验证。具体流程和验证安排见技术设计。

| 编号 | 可观察的验收条件 |
| --- | --- |
| AC-01 | 创建外部 URL 内容后取得 `/r/<12位ID>` 分享地址，访问后正确跳转；修改目标后地址不变，KV 状态收敛后按新目标跳转，浏览器不缓存旧跳转 |
| AC-02 | 本地上传完成且大小、SHA-256 校验通过后，图片可直接展示，其他文件默认下载；返回字节与已发布文件一致，未完成或校验失败不报告发布成功 |
| AC-03 | 多次上传同名文件后，各资源仍可独立访问和管理 |
| AC-04 | 未认证者不能列出、编辑、删除资源或查询统计；持有分享链接即可公开读取，不需要管理凭据 |
| AC-05 | 图片和其他文件不能覆盖原内容，更新创建新资源；旧资源保留到主动删除，旧 ID 不分配给其他内容 |
| AC-06 | 删除分别返回逻辑状态、KV 更新和文件清理结果；允许传播延迟，状态收敛后服务端各路径均拒绝原文件或跳转，包括边缘缓存命中；浏览器已有副本不承诺收回 |
| AC-07 | 验证缓存命中、未命中、分段、重试、机器人及预览路径；每个符合口径的 GET 恰好提交一次采集，含删除传播期间仍成功的请求；HEAD、失败及已拒绝请求不计数，采样结果按权重计算 |
| AC-08 | 通过 Agent 接口可查询访问次数、时间趋势、来源及地区分布和热门资源，无需进入 Cloudflare Dashboard |
| AC-09 | 所有首版管理能力可经 Agent 接口完成，产品不依赖自建管理 GUI |
| AC-10 | 未配置可选限制时不额外设置产品容量、单文件大小、数量或频率上限；配置后原子预留空间，已发布、上传预留、待清理占用均被计入，超限或大小不符明确拒绝，不能重复释放额度 |
| AC-11 | 标题、描述和标签可填写与编辑，支持标题和描述搜索、标签筛选；这些操作不改变文件字节或分享地址 |
| AC-12 | 产品统计和样本查询范围为最近 30 天；正常情况下访问在 5 分钟内反映到统计，不要求长期累计或到第 30 天物理删除平台数据 |
| AC-13 | 删除前后的同一历史时间范围中，该资源仍贡献其历史访问并标记为已删除；修改短链目标不重置资源统计，不提供按历次目标拆分 |
| AC-14 | 采集保留实际 Referer 原文，MCP 格式化不取代原始值；来源和地区缺失时表示未知，地区细度不超过平台实际提供的信息 |
| AC-15 | 访问样本查询有筛选和返回量限制，按接口契约分批返回；结果明确为平台可获取样本并保留可用权重，不宣称完整日志，不通过额外存储或自行采样补全记录 |
| AC-16 | 可模拟的统计采集故障不阻断文件访问或跳转，能检测到的故障有异常记录；统计查询失败明确报错，不返回伪造的零访问 |
| AC-17 | 首版不要求解析类型专属属性；后续扩展设计说明如何为已有资源补充属性，无需重新上传且不改变分享链接 |
| AC-18 | Codex、Hermes 经 OAuth 使用 MCP；应用 Token 可连续上传、24 小时到期及主动撤销生效；OAuth 撤销与应用 Token 撤销的独立边界有明确说明 |
| AC-19 | MCP 仅列出 `describe`、`invoke`；目录、参数定义与实际 operation 一致，错误和部分完成状态可由 Agent 读取 |
| AC-20 | 模拟创建成功后响应丢失，以原操作标识查询或重试得到同一资源；不同创建参数复用标识会报冲突，主动重复上传仍生成独立资源 |
| AC-21 | 图片、文件返回一年浏览器缓存策略，短链返回 `302 + no-store`；浏览器本地复用不计统计，管理和错误响应不被公开缓存 |
| AC-22 | SVG 原始字节不变，以 `image/svg+xml` 由浏览器展示，不添加额外 CSP、脚本或外部资源限制 |
| AC-23 | Cron 每 5 分钟扫描到期操作，按退避规则每轮最多自动重试 10 次；之后可查询 `needs_attention` 并手动恢复，不误清理活跃上传或提前释放容量 |
| AC-24 | 关键词搜索、默认 20 条及最多 100 条、倒序游标分页符合约定；按指定时区正确划分小时和日期，响应包含实际范围及时区 |
| AC-25 | 命令行初始化可重复执行，迁移与升级保留已有数据和分享 URL；Access/OAuth 一次性配置有可执行文档 |
