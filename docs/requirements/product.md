# cf-content-share 产品需求

- 状态：需求草案，尚未实现。
- 更新日期：2026-10-10。
- 使用场景：个人自部署，或供少量可信用户使用。

本文记录当前讨论形成的产品需求。首版功能清单和验收标准作为后续设计的基线；技术方案为当前建议，待定事项不视为已确认要求。

## 1. 产品定位

将网址、图片和其他文件变成可访问、可管理、可统计的分享链接，通过 Agent 完成管理。

产品以内容分享为中心：网址生成跳转链接，托管文件生成直接访问或下载链接。所有内容共享资源标识、用户归属、管理能力和访问统计。

项目基于 Cloudflare 生态自行实现，不提供自建管理 GUI。MCP 是管理入口，公开分享地址使用普通 HTTPS，访问者无需使用 MCP。

## 2. 已明确的范围与约束

1. 支持外部 URL、图片和其他文件。
2. 管理操作及统计查询通过 MCP 等 Agent 接口提供。
3. 支持多用户归属，用户只能管理和查询自己有权限访问的资源及统计。
4. 每条内容拥有独立短 ID，不以原文件名作为唯一标识。
5. 图床不提供图片内容编辑或原 URL 覆盖功能。
6. 访问统计属于正式功能，不能因使用缓存而遗漏到达服务的有效资源访问请求。
7. 用户视为可信，默认不限制内容数量或创建频率。
8. 总容量和单文件大小可以作为部署者可选的限制，具体默认值尚未确定。
9. 基础设施必须对应实际需求，优先采用简单、可维护的方案。

首版以公开分享为目标。管理权限与内容读取权限分别定义；持有公开 URL 的访问者可以读取内容，资源归属不代表内容私有。私有内容、限时分享和访问密码尚未确定。

## 3. 内容与资源模型

底层统一表达为：短 ID → 资源记录 → 对外响应。

| 资源类别 | 保存的内容 | 公开访问行为 |
| --- | --- | --- |
| 外部引用 | 目标 URL 和管理元数据 | 返回 HTTP 重定向 |
| 托管图片 | 文件、文件属性和管理元数据 | 返回可直接展示或嵌入的图片 |
| 其他托管文件 | 文件、文件属性和管理元数据 | 提供文件读取或下载 |

图片属于托管文件的一种。统一业务概念不要求立即采用同一张数据库表，具体 Schema 留到设计阶段确定。

### 3.1 资源标识与分享地址

- 服务端生成足够长度的随机短 ID，并在创建时保证唯一性，防止覆盖已有资源。
- 不同用户以及同一用户上传同名文件，必须生成互不冲突的资源记录。
- 原文件名作为显示或下载信息保存，不参与资源唯一性判断。
- 资源 ID 与分享地址在资源存续期间保持稳定；删除后不得将旧 ID 分配给另一条内容。
- 完整公开 URL 可以由部署域名和资源 ID 生成，无需逐条持久保存完整 URL。
- R2 对象 key 可以由资源 ID 按固定规则生成；如果与 ID 解耦，必须持久保存对应关系。
- 统一域名、URL 路径格式、ID 长度与字符集、自定义别名留到设计阶段确定。

### 3.2 管理元数据

| 范围 | 信息 |
| --- | --- |
| 公共记录 | 资源 ID、资源类别、归属用户、创建时间 |
| 外部引用 | 目标 URL |
| 托管文件 | R2 文件定位信息、原文件名、内容类型、实际字节大小 |
| 图片属性 | 宽度、高度、是否为动图；支持格式和解析方式待定 |
| 可选描述 | 标题、描述、标签；是否纳入首版及是否允许编辑待定 |

文件属性以服务端核验结果为准。标题、描述和标签属于管理元数据；修改这些信息与修改文件内容是不同能力，需分别确定范围。

## 4. 首版功能基线

| 编号 | 功能 | 预期行为 |
| --- | --- | --- |
| FR-01 | 创建 URL 内容 | 保存目标网址，分配独立短 ID，返回分享地址；访问后跳转到目标 |
| FR-02 | 上传托管内容 | 保存图片或其他文件，建立资源记录，确认上传完成后返回可用分享地址 |
| FR-03 | 列出与查找内容 | 分页列出本人资源，按资源类别、原文件名和创建时间筛选；描述字段确定后再扩展对应搜索 |
| FR-04 | 查询内容详情 | 返回资源信息、文件属性和分享地址 |
| FR-05 | 删除内容 | 检查权限后删除资源；托管内容同时处理文件与缓存，不得仅删除管理记录 |
| FR-06 | 查询单条内容统计 | 按时间范围返回访问次数、时间趋势、来源及地区分布 |
| FR-07 | 查询汇总与排行 | 返回本人内容的汇总统计及指定时间范围内的热门资源 |

上传失败或未完成时，不得将内容报告为发布成功。失败和重复请求的处理方式、文件与元数据的一致性机制，留到技术设计阶段确定。

图片更换内容必须作为新资源上传并生成新 ID。其他文件的替换行为、短链目标修改和元数据编辑尚未确定。

## 5. 访问统计

### 5.1 正式统计能力

- 单条资源在指定时间范围内的访问次数。
- 按天或小时聚合的访问趋势。
- 请求来源及访问地区分布；缺失数据应明确表示未知。
- 指定用户、资源类别和时间范围下的汇总与热门排行。
- 所有统计均可通过 Agent 接口查询，不依赖用户进入 Cloudflare Dashboard。

统计查询由服务端验证权限，并限制到授权用户和资源。返回结构化聚合结果，供 Agent 解释或展示。

### 5.2 统计口径

基础口径是到达服务的资源访问请求，不代表人眼观看次数、独立访客数或完成下载次数。

- 浏览器使用本地缓存而未发送网络请求时，不产生新的服务端访问事件。
- 服务端响应缓存命中时，访问请求仍必须进入统计采集路径。
- 分段下载、重试、HEAD 请求、链接预览和机器人请求的计数规则需在实现前确定。
- 不同资源类别可以分别报告跳转请求、图片读取请求和文件读取请求。
- Analytics Engine 查询必须考虑采样权重，不能直接把记录行数当作访问次数。
- 是否需要严格精确计数、UV、去重、实时性保证和长期累计值，尚未确定。

统计采集失败及查询失败的处理方式需明确，不能把查询失败伪装成零访问量。数据保留期限及是否保存长期聚合结果待定。

## 6. 缓存与删除

缓存目标是公开文件的 HTTP 响应，包括文件内容与相关响应头，以减少重复读取 R2。

- 图片内容不覆盖原 URL，允许采用较长的服务端缓存有效期。
- 浏览器缓存时间与边缘缓存时间分别配置，兼顾访问效率与删除生效时间。
- 管理接口、认证相关响应和失败响应不应进入公开内容缓存。
- 删除后必须阻止服务端继续提供已删除内容，并处理对应缓存的失效。
- 已到达浏览器或已下载的副本无法由服务端收回，浏览器缓存行为必须与删除语义一起说明。
- 缓存策略不得改变用户权限或导致不同用户的管理数据混用。

具体 TTL、删除生效边界和缓存清除机制尚未确定。本需求不固定采用前期举例的一年边缘缓存或五分钟浏览器缓存。

## 7. 自部署与成本边界

- 使用者为可信用户，默认不设置内容条数上限、每日新增条数上限或创建频率限制。
- 总存储容量、用户容量及单文件大小限制均为可选配置，当前不固定数值。
- 上传实现必须遵守平台能力，并核验实际文件大小；配置了容量限制时，并发上传不得绕过限制。
- 不因费用预设下载流量 GB 配额。R2 Standard 的费用由存储占用和操作次数构成，出站流量免费。
- 短期分享后清理文件可以减少后续存储占用，但每日峰值仍计入存储用量，不能承诺短期大容量内容必然免费。
- 使用缓存仍可能产生 Worker 请求与 CPU 消耗；统计采集也必须纳入用量观测。
- 部署者应能查看实际资源用量、失败请求及费用相关指标。

文件类型白名单、图片直接展示范围、其他文件的下载响应方式及到期清理能力待定。任何限制都应有明确用途，避免把自用产品设计成复杂的套餐系统。

## 8. 当前建议的 Cloudflare 方案

本节是技术设计的起点，不表示代码、部署或长期架构决定已经完成。

| 组件 | 当前建议职责 |
| --- | --- |
| Workers | Agent 管理接口、公开资源访问、身份与权限检查、统计采集与查询 |
| D1 | 资源记录、URL 映射、管理元数据、用户归属 |
| R2 Standard | 托管文件的持久存储 |
| Cache API | 在 Worker 内缓存公开文件响应，命中时仍经过访问采集逻辑 |
| Workers Analytics Engine | 保存访问事件，通过查询 API 提供聚合统计 |
| Workers Logs / Metrics | 观察请求、错误和运行用量 |

推荐的文件访问路径：

```text
公开请求 → Worker 校验资源状态并执行统计采集
        → Cache API 命中：返回缓存文件
        → Cache API 未命中：读取 R2，返回并缓存文件
```

注意区分两种缓存机制：Workers Cache 可以在命中时跳过 Worker；Cache API 在 Worker 内运行。当前方案优先保障访问采集，不能直接用跳过 Worker 的缓存替换它并沿用原统计口径。

Cache API 的缓存按数据中心保存，`cache.delete()` 只清除当前数据中心的副本。删除设计必须提供跨节点失效方案，或在返回缓存内容前检查资源删除状态；不得把本地清除当作全局清除。

KV 仅在明确出现额外缓存或配置需求时考虑，不默认复制 D1 中的资源映射。Queues、Cron Triggers、Images Transformations 等能力，只有出现相应后台任务或内容处理需求时才引入。

## 9. 待定事项

| 主题 | 需要确定的内容 |
| --- | --- |
| 身份与权限 | 可信用户如何配置、使用何种认证、管理员权限范围 |
| 分享权限 | 是否支持私有内容、限时分享、访问密码 |
| 编辑能力 | 是否允许修改短链目标、标题、描述、标签，以及替换其他文件 |
| Agent 接口 | MCP 工具边界、参数、结果、错误与重复请求处理 |
| 文件传输 | 本地文件如何到达远程服务，是否支持 URL 导入、分片和断点续传 |
| 大小与类型 | 是否设置默认容量和单文件上限、支持的展示格式和下载策略 |
| 地址规则 | 自定义域名、公开路径、ID 格式、自定义别名 |
| 统计契约 | 精度、UV、机器人及 HEAD 过滤、分段请求、时间区间与时区、查询延迟、保留期限 |
| 缓存与生命周期 | 各层 TTL、删除生效时限、失败上传清理、是否支持内容到期 |
| 数据模型 | 数据表布局、文件 key 规则、文件与元数据一致性及恢复方式 |

Agent 交互和上传传输细节将在基础需求确定后单独讨论。

## 10. 验收标准

以下为后续实现的验收目标，不表示目前已通过验证。待定契约确认后，应补充相应的具体参数与边界。

| 编号 | 可观察的验收条件 |
| --- | --- |
| AC-01 | 创建外部 URL 内容后，可取得独立分享地址，访问后正确跳转 |
| AC-02 | 图片可通过分享地址直接展示，其他文件可读取或下载，返回字节与已发布文件一致 |
| AC-03 | 同一用户及不同用户上传同名文件后，各资源仍可独立访问和管理 |
| AC-04 | 用户不能列出、删除或查询未获授权的其他用户资源及统计 |
| AC-05 | 图片内容不覆盖原分享地址，更换图片会创建新资源；旧 ID 不分配给其他内容 |
| AC-06 | 删除后原数据不可再由服务端读取，缓存访问符合已确定的删除生效契约 |
| AC-07 | 缓存命中的有效访问仍执行采集；在未采样的测试流量下，按已确定口径验证事件与统计变化 |
| AC-08 | 通过 Agent 接口可查询访问次数、时间趋势、来源及地区分布和热门资源，无需进入 Cloudflare Dashboard |
| AC-09 | 所有首版管理能力可经 Agent 接口完成，产品不依赖自建管理 GUI |
| AC-10 | 未配置可选限制时，不因内容数量或创建频率而拒绝可信用户；配置了容量限制时按实际字节正确执行 |
