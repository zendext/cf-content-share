# 架构与一致性

[English](../en/architecture.md) · [文档入口](../../README.zh-CN.md#文档)

## 组件与信任边界

同一个 Rust/Wasm Worker 处理三条入口及五分钟 Cron：

| 入口 | 认证与职责 |
| --- | --- |
| `/mcp` | Access Managed OAuth；Worker 验证 Access JWT，处理 `describe` / `invoke` |
| `POST /upload` | Worker 验证应用级 Bearer Token，流式写入 R2 |
| `GET/HEAD /r/<id>` | 公开访问；检查资源状态后跳转或读取正文 |
| scheduled | 恢复已登记操作，清理到期资源和文件 |

Access 只保护 `/mcp`，不把整个域名置于登录墙后。JWT 校验包括签名、issuer、audience 和时间。上传 Token 仅用于上传，有效期固定 24 小时，D1 只保存摘要。OAuth 撤销不自动撤销已签发的上传会话。

## 状态来源

D1 是资源、会话、操作、执行租约及容量计数的权威来源；KV 是公开映射的派生副本；R2 保存私有正文。Analytics Engine 单独保存访问事件。D1、KV 和 R2 之间没有跨服务事务。

[`src/store/`](../../src/store/) 集中承载 D1 SQL 和类型化数据访问；业务模块负责校验、状态转换和外部服务调用。SQL migration 是持久 Schema 的来源，MCP `describe` 是调用参数与结果契约的发现入口。

资源有 `pending`、`published`、`deleted` 状态。操作保留各步骤、累计尝试、最近错误和重试安排；逻辑删除、KV 接受更新、R2 清理完成是不同事实。创建和上传的操作 ID、参数指纹与资源映射持久化，重试返回同一资源的当前状态。删除后的 ID 与操作映射保留，避免复用或复活旧链接。

## 文件与容量

上传先在 D1 原子登记资源、操作和容量预留，再以不可变尝试 key 向 R2 流式写入，核对归属、大小与原生 SHA-256 后才发布。总占用为 `published_bytes + reserved_bytes + cleanup_bytes`；条件写入和 SQL trigger 保证每次转移只计数一次。

每次尝试有独立 key 和执行 Token。30 秒心跳维持 120 秒租约；超时允许恢复者核对，不允许直接释放空间。恢复通过 create-only 零字节屏障阻止旧写入后来提交，或核验已完成对象。屏障永久保留；来源不明的对象进入人工处理，不擅自删除。详细规则见[上传与恢复](files.md)。

## KV、期限与缓存

公开读取先检查映射及期限，缺失、格式无效或失效时回源 D1。快照从最初 D1 读取前的 `observed_at` 起最多有效 86400 秒；KV 使用同一绝对截止，缓存命中和迟到回填不续期。剩余不足 60 秒不回填。D1 与 KV 都不可用时返回 503，不绕过状态检查读取正文缓存。

到已知期限时回源确认是否续期；确认到期返回 404，不等 Cron。删除或目标更新存在 KV 传播延迟。Cache API 只缓存完整 200，边缘缓存为 86400 秒；浏览器收到 `private, max-age=31536000, immutable`。单个节点的缓存删除不代表全局清除，浏览器副本无法收回。短链使用 `302` 与 `no-store`。

资源在首次发布时确定期限，普通编辑、访问和重试不会重新计时。

## 恢复与统计

Cron 每次最多扫描 25 个到期资源、处理 25 个恢复任务。删除条件在 D1 写入时重检，状态和清理任务同事务登记。重试间隔为 5、10、20、40 分钟，之后每小时；每轮最多自动重试 10 次，手动恢复保留累计次数和错误。需要客户端文件正文时不能由 Cron 自动补传。

公开出口对成功 GET 的 302、200、206 各采集一次。HEAD 和错误不采集；范围请求、机器人和预览照常计数。统计按 `_sample_interval` 加权，不承诺完整访问日志；采集失败不改变分享响应，查询失败不伪造零值。详见[统计](analytics.md)。

## 验证边界

`npm run check` 覆盖格式、类型、构建和本地 workerd 回归，包括故障注入。测试夹具中的故障开关不进入生产代码。本地测试与 dry-run 不证明真实 Access 客户端兼容性、跨节点 KV 传播、云端并发故障恢复或浏览器长期缓存行为；这些需要部署后的针对性验证。
